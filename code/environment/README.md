# Environment notes

This file documents the minimum execution environment required to regenerate the frozen paper-specific source-data files in this repository package.

## Scope

These notes apply to the scripts in:

- code/scripts/generate_paper_source_data.py
- code/scripts/regenerate_source_data.sh
- code/scripts/run_inventory_soc_simulation.sh
- code/scripts/simulate_inventory_soc.py
- code/scripts/verify_paper_source_data.py
- code/scripts/verify_source_data.sh
- code/scripts/release_paper_source_data.sh
- code/scripts/stage_external_package.sh

They do not describe the full BigLoI monorepo runtime, frontend build, API server, or TIFF export pipeline.

## Exact tested environment

- OS: macOS Darwin 25.3.0
- Shell: GNU bash 3.2.57(1)-release (arm64-apple-darwin25)
- Python: 3.13.2
- Python environment type: virtual environment
- Tested Python executable in this workspace: /Users/andressoto/BigLoI/.venv/bin/python

## Python requirements

The source-data generator and the exploratory inventory-criticality simulator use only Python standard library modules:

- argparse
- csv
- dataclasses
- json
- math
- pathlib
- random
- statistics

No third-party Python packages are required to regenerate the CSV and Markdown outputs covered by this paper package or to run the exploratory SOC-style simulation.

## Recommended command

From the workspace root:

```bash
bash docs/publicacion_cientifica/paper_repository_plosone/code/scripts/regenerate_source_data.sh
```

This is the recommended entry point because it:

- prefers the project virtual environment when available;
- falls back to python3 if the virtual environment is absent;
- runs from the repository root using stable relative paths.

## Recommended verification command

From the workspace root:

```bash
bash docs/publicacion_cientifica/paper_repository_plosone/code/scripts/verify_source_data.sh
```

This wrapper follows the same environment resolution logic as the regeneration wrapper and is the preferred way to validate the frozen paper package before release.

## Recommended exploratory simulation command

From the workspace root:

```bash
bash docs/publicacion_cientifica/publish_ready/BigLoI-PLOS-ONE-paper/code/scripts/run_inventory_soc_simulation.sh
```

Optional example with custom horizon and seed:

```bash
bash docs/publicacion_cientifica/publish_ready/BigLoI-PLOS-ONE-paper/code/scripts/run_inventory_soc_simulation.sh --days 1825 --seed 7
```

This wrapper follows the same environment resolution logic as the other shell entry points and writes outputs under:

```text
docs/publicacion_cientifica/publish_ready/BigLoI-PLOS-ONE-paper/code/results/inventory_soc/
```

## Recommended release-preparation command

From the workspace root:

```bash
bash docs/publicacion_cientifica/paper_repository_plosone/code/scripts/release_paper_source_data.sh
```

This command is the preferred pre-release step for the paper package because it regenerates the frozen outputs first and then verifies that all expected files and headers remain correct.

This command is intended for external publication prep. It runs the release-preparation step and then creates a publish-ready standalone copy of the package inside the project workspace.

## Reproducibility note

These scripts regenerate the frozen paper package, not a live export from changing APIs or databases. This is intentional: the goal is to preserve the article-specific scientific record exactly as packaged for submission.

## When a different environment is needed

If the goal is to rebuild figures from live application data, re-query APIs, or regenerate editorial TIFF assets, use the broader project tooling outside this paper-specific package. Those tasks require additional dependencies not covered here.

If the goal is to calibrate the exploratory simulation against real hospital inventory traces, supplier lead-time logs, or item-level dispensing data, additional datasets and likely third-party scientific packages will be needed. The bundled simulator is intentionally lightweight and scenario-based.
